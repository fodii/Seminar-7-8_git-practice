## Ожидаемый ответ

После rebase базовая ветка должна быть предком
feature-ветки. Перенесённые коммиты должны получить
новые SHA, без создания merge-коммита.

## Моё объяснение

Сначала я создал новый коммит в ветке base/task-02,
изменив строку в файле message.txt.

Затем переключился в feature/task-02 и сохранил
исходную историю тегом evidence/02-before.

При выполнении rebase возник конфликт, потому что
две ветки изменили одну и ту же строку по-разному.

Я разрешил конфликт, сохранив оба сообщения:

Сообщение: изменение из base
Сообщение: изменение из feature

После git add и git rebase --continue перенос
коммитов успешно завершился.

Сравнение git range-diff показало, что первый
старый и новый коммиты не были сопоставлены из-за
изменившегося патча после разрешения конфликта.
Второй коммит получил знак =, то есть изменения
этого коммита совпали.

Проверка git merge-base --is-ancestor подтвердила,
что обновлённая база является предком результата.

После force-push ветка была обновлена на GitHub.
Рабочая директория осталась чистой.
